广交会移动端实时对账核对系统 · 取餐核对台

针对展会 20+ 部门多品牌餐券手工抄录易错漏、现场余量不透明的痛点，独立构建并上线运行了手机端实时核对系统，覆盖 33 天完整展期，保障高压现场账目零错漏。

业务现场与解决思路

展会配餐现场节奏极快，每个餐次需核对 20 多个部门在 5 大餐饮品牌与白饭上的报餐、实取、换餐、加餐与供应商实际到餐差额。传统纸质抄录加共享表格事后汇总，导致“谁超报、谁漏拿、备用还剩几份”无法在发餐瞬间发现。我用 Node.js + 原生移动端网页搭建了「取餐核对台」，现场用手机点选登记、多端秒级同步，彻底把事后查账变成事中防呆。

多端实时同步与容灾
自建 Node.js 服务 + SSE 实时推送 + FRP HTTPS 穿透，多台手机同步核对；现场断网时自动降级 `localStorage` 本地读写，绝不中断发餐。
云端表格交叉稽核
通过金山文档 AirScript 自动读取每日报餐表与核对表，自动识别单元格标红字体做格式与数字一致性校验，共完成 31 次异常确认。
防呆校验与离线归档
登记时强制校验人数等于餐份、超报即时拦截标红；日结一键将少取部门转入待补餐券清单，并内置零依赖纯前端 OOXML 生成器，断网亦可导出标准 `.xlsx`。

商业机制与工程演进

项目最大的壁垒不只是把流程自动化，而是同时解决了效率、信任与履约上限三个问题：前端用 34 个 Express REST 接口支撑自助选课下单、首次短信验号与进度查询，并把首屏 4 次请求合并为 `/api/bootstrap` 节省内网穿透流量；后端从浏览器模拟演进到纯 Python 协议直连，更设计了「占位账号征用协议」—— 37 位客户自愿出借空闲名额参与占位，系统完成 216 次名额置换并反向掉落 35 次免费热门活动，形成双边名额调度池与高粘性复购。

纯 HTTP 协议直连
排查还原请求体 SM4 / AES 加解密与签名逻辑，开抢前自动执行 `preflight` 校验，并配合 `snipe_analyzer` 分析毫秒级抢单日志做节奏调优。
自动抓取与信息补全
后台定时抓取校园新活动并自动补全海报、介绍与综测加分细则，客户端按未浏览、线上线下与重复活动自动分层展示。
履约复核与自动生图
抢报后支持批量复核真伪，一键生成带客户明细的「待结账单快照图片」发给客户结算，配合内置工单与公告系统实现低纠纷运营。
